# PRD: Observability

**Tier:** 4 &nbsp;·&nbsp; **Status:** Proposed &nbsp;·&nbsp; **Owner:** TBD

## Problem
Today the app has nothing operators need to run it in production: log output is plain `print`/Django default text, errors are not aggregated anywhere, and there is no health endpoint a load balancer or container orchestrator can probe. The first time a user hits a 500 in prod, we'd hear about it from the user — and we'd have no trace ID to correlate logs across the request. Every Tier 1–3 PRD that ships features assumes "if something breaks, we will notice" — which is not yet true.

## Goals
- Every log line is structured JSON with a stable request ID, route, user ID (if any), and latency.
- Unhandled exceptions surface in Sentry with full request context within seconds.
- `/healthz` (liveness) and `/readyz` (readiness, checks DB + cache) return correct codes for orchestrator probes.

## Non-Goals
- Prometheus metrics / Grafana dashboards — defer to a future PRD once we have actual prod traffic to measure. Premature dashboards just become noise.
- Distributed tracing (OpenTelemetry). Single-service Django doesn't need spans; revisit when background workers (40.02) start fanning out.
- Log shipping infrastructure (Loki, Datadog). JSON to stdout is enough — the deploy target's log collector handles the rest.

## User Stories
- As an operator, I can grep one request ID across all log lines and see the whole journey.
- As an operator, I get a Sentry alert with stack trace, route, and user ID when a 500 happens.
- As an SRE, my orchestrator's readiness probe fails when the DB is unreachable, so traffic stops being routed to a broken pod.
- As a developer debugging staging, I see the same JSON shape locally that I see in prod.

## UX Sketch
No user-visible UI. Operators see: structured logs in stdout (one JSON object per line), Sentry's web UI for issues, and HTTP probes returning 200/503. A small `helpers/logging.py` exposes a `get_logger(__name__)` shim so app code stays portable if we swap libs later.

## Data Model Changes
None.

## Key Technical Decisions
- **Use stdlib `logging` + `python-json-logger` formatter, not `django-structlog`.** Rationale: stdlib is already in every Django app, the formatter adds ~100 lines of `LOGGING` config, and we don't need structlog's bound-logger ergonomics for a small codebase. django-structlog is the alternative — nicer API, but a dep we don't yet need.
- **Request ID middleware**: thin custom middleware reads `X-Request-ID` (or generates a UUID4), binds it to a `contextvars.ContextVar`, and emits it back as a response header. The JSON formatter pulls from the contextvar.
- **Sentry**: `sentry-sdk[django]` — official Django integration auto-instruments views, ORM, and the logging handler. Dial sample rate via `SENTRY_TRACES_SAMPLE_RATE` env var.
- **Health endpoints** live in a new `apps/ops/` (or in `helpers/views.py`) — `/healthz` returns 200 unconditionally; `/readyz` runs a `SELECT 1` and a cache `get`/`set` round-trip.

## Risks & Open Questions
- **PII in logs.** Don't log request bodies or `request.POST`. Add a Sentry `before_send` scrubber for `password`/`email` fields.
- **100% coverage gate.** Sentry init and the JSON formatter need `# pragma: no cover` for the prod-only branches (same pattern as `config/settings.py`).
- **Open question:** is `/readyz` allowed to fail during a long migration? Recommendation: yes — that's the point of readiness vs. liveness.

## Success Metrics
- 0 plain-text log lines in stdout under `DEBUG=False`.
- <30s from exception raised to Sentry issue created.
- Liveness/readiness endpoints have unit tests covering the failure paths.

## Rough Effort
S — one middleware, one settings block, one new dep (`sentry-sdk`), two trivial views. No migration risk.

## Dependencies
- **Unblocks:** every Tier 1–3 PRD that adds a code path worth observing — most directly **10.01 Password Reset** (need to see mail-send failures), **20.01 Notifications** (fan-out errors), and **40.02 Background Jobs** (worker errors must reach the same Sentry project).
- **Blocked by:** none. Land this first.
