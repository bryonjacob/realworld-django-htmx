# PRD: Editor Improvements

**Tier:** 3 &nbsp;·&nbsp; **Status:** Proposed &nbsp;·&nbsp; **Owner:** TBD

## Problem
`ArticleForm` today is three plain `<textarea>`s — `title`, `description`, `body` — with zero editor affordances. Authors lose work to accidental tab-closes, can't paste images, can't preview their Markdown without publishing, and have no formatting helpers. For a blogging app that wants to feel modern, the writing surface is the single most important UX moment, and ours is the weakest part of the product.

## Goals
- Drafts autosave every few seconds so closing the tab never loses work.
- Authors can paste or drag images directly into the body and get a working Markdown image link.
- Authors can toggle a live Markdown preview without leaving the page.
- A small toolbar (or `/`-slash menu) gives one-click bold/italic/heading/link/code.

## Non-Goals
- Rich-text WYSIWYG (we stay Markdown-first — the source is the source of truth).
- Collaborative / real-time multi-author editing.
- Versioning and diffing of drafts (a separate Tier 4 PRD).
- Mobile-specific editor polish beyond what the chosen library gives for free.

## User Stories
- As an author, I can leave the editor and come back to find my draft preserved.
- As an author, I can paste a screenshot and have it appear inline as Markdown.
- As an author, I can click a "Preview" toggle and see the rendered article side-by-side or in place.
- As an author, I can hit a toolbar button to wrap selected text in `**bold**`.
- As an author with a flaky connection, I see an unobtrusive "saving…" / "saved" indicator.

## UX Sketch
The Create / Edit Article page (`articles/article_form.html`) gains a thin toolbar above the body textarea and a `[Preview]` toggle that swaps the textarea for the rendered Markdown via the existing `render_markdown` template tag. Autosave is a debounced HTMX `hx-post` (e.g. `hx-trigger="input changed delay:1500ms"`) targeting a new `article_autosave_view` that returns just a small status partial (`Saved 2s ago`). Image paste is captured by a small Alpine.js handler that uploads to a new `image_upload_view` and inserts the resulting Markdown at the cursor.

## Data Model Changes
- `Article.is_draft: BooleanField(default=False)` — distinguishes autosaved-but-never-published from published. Filter all public feeds on `is_draft=False`.
- New `ArticleImage` model: `article (FK, nullable for orphan uploads), uploader (FK User), image (ImageField), created`. Nullable FK so an image uploaded in a brand-new draft (no `Article.pk` yet) can be claimed on first save.
- Storage: local `MEDIA_ROOT` for v1; S3 via `django-storages` is a config swap when needed.

## Key Technical Decisions
- **Alpine.js + a thin custom layer over a plain `<textarea>`** rather than EasyMDE or TinyMCE. Alpine is already the natural complement to HTMX; a heavyweight editor lib fights HTMX swap semantics and bloats page weight. EasyMDE was the alternative considered — nicer out-of-box toolbar but ~60KB and awkward to wire to HTMX autosave.
- Autosave endpoint reuses `ArticleForm` with a relaxed validator (allow blank `title` for in-progress drafts), gated to the article's author.
- Live preview hits the server (`/articles/preview` returning sanitized HTML via the existing `nh3.clean()` pipeline) rather than rendering Markdown client-side — keeps one source of truth and reuses sanitization.
- Image upload limit: 5MB, types `image/png|jpeg|gif|webp`, validated server-side.

## Risks & Open Questions
- **Risk:** Autosave write amplification — every keystroke debounced to 1.5s still produces many writes per article. Mitigation: only persist when content actually differs from last saved state.
- **Risk:** Orphan `ArticleImage` rows from abandoned drafts. Mitigation: nightly management command to GC images older than 30 days with no `article` FK.
- **Open question:** Slash-command menu vs. visible toolbar — slash is trendier but discoverability is worse. Recommend toolbar for v1, slash later.

## Success Metrics
- 0 user reports of "lost my draft" within 90 days of launch.
- Median time-to-first-publish for new authors drops (proxy: signup → first published article).
- Preview toggle used in >40% of edit sessions (instrumented click).

## Rough Effort
L — new model + migration, new view surfaces (autosave, preview, image upload), Alpine.js integration, real e2e coverage of paste/preview/autosave.

## Dependencies
- **10.05 Markdown Rendering Hardening** (Tier 1) — the live preview reuses that pipeline; if Markdown rendering is still inline-and-untrusted, preview ships the same risk.
- **10.01 Password Reset and Email Verification** (Tier 1) — autosave + image upload should be gated on verified accounts to prevent abuse as a free file host.
