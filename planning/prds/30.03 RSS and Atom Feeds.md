# PRD: RSS and Atom Feeds

**Tier:** 3 &nbsp;·&nbsp; **Status:** Proposed &nbsp;·&nbsp; **Owner:** TBD

## Problem
There's no machine-readable way to subscribe to articles. Readers who use feed readers (NetNewsWire, Feedly, Inoreader, Miniflux) have no entry point — they can't follow an author, a tag, or the global firehose without opening the site every day. For a blogging platform, RSS is table-stakes; its absence quietly tells power users we don't take their reading habits seriously.

## Goals
- A global feed at `/feed.xml` (and `/feed.atom`) covers the latest published articles site-wide.
- A per-author feed at `/@<username>/feed.xml` covers that author only.
- A per-tag feed at `/tag/<slug>/feed.xml` covers that tag only.
- Each feed entry includes full sanitized HTML content, canonical link, author, published timestamp, and tags as categories.
- Feed URLs are auto-discoverable via `<link rel="alternate">` tags in the HTML head of the matching pages.

## Non-Goals
- WebSub / PubSubHubbub push hubs — pull-only is fine for v1.
- Authenticated feeds (private articles, your "Following" feed as a personalized RSS). Considered, but auth-via-token in feed readers is a UX swamp; revisit if there's demand.
- JSON Feed alongside RSS+Atom — easy to add later if asked, no demand signal yet.

## User Stories
- As a reader, I can subscribe to `/@johndoe/feed.xml` in my feed reader and see new articles from John appear automatically.
- As a reader, I can subscribe to a tag like `/tag/django/feed.xml` and follow a topic without following individuals.
- As a reader using a smart browser, the feed icon appears in my address bar because the page advertises its feed.
- As a reader, I can read the full article text in my feed reader without clicking through.

## UX Sketch
No new visible pages — feeds are XML endpoints. Three new URL routes wired up via `django.contrib.syndication.views.Feed` subclasses. The home page, profile pages, and tag pages each gain a `<link rel="alternate" type="application/rss+xml" ...>` tag in the head. A small "Subscribe via RSS" link with a feed-icon SVG goes in the page footer or near the relevant feed header for direct discoverability.

## Data Model Changes
None. Feeds are read-only views over the existing `Article` queryset.

## Key Technical Decisions
- **Use `django.contrib.syndication.framework`** rather than a third-party feed lib (e.g. `feedgen`). It's in the standard distribution, already integrated with URL routing, and supports both RSS 2.0 and Atom from the same `Feed` class via `feed_type`. `feedgen` was the alternative considered — more flexible, but a new dependency for capability we already have.
- Three `Feed` subclasses: `GlobalArticleFeed`, `AuthorArticleFeed`, `TagArticleFeed`. They share a base mixin that sets `description_template` and reuses the `render_markdown` template tag for `item_description` so feed HTML matches site HTML exactly (one sanitization pipeline).
- Cap each feed at the 20 most recent articles. Order by `-created`.
- Set `Last-Modified` and `ETag` headers via Django's conditional view decorators so well-behaved readers get cheap 304s. Critical for cost — feed readers poll relentlessly.
- Cache rendered feed XML for 5 minutes (`cache_page(300)`) — feed updates aren't real-time-critical and this absorbs poll bursts.

## Risks & Open Questions
- **Risk:** A misconfigured aggressive reader hammers `/feed.xml` from many IPs. Mitigation: the 5-minute cache absorbs most of it; rate-limit per-IP via `django-ratelimit` if needed.
- **Risk:** Markdown content with raw HTML or relative links breaks in feed readers. Mitigation: the existing `nh3.clean()` allowlist already strips dangerous markup; rewrite relative `<a href>` and `<img src>` to absolute URLs in the description renderer.
- **Open question:** Include comments in feeds, or only the article body? Recommendation: body only — comments would invalidate the cache constantly.

## Success Metrics
- Feeds validate clean against the W3C feed validator for all three URL shapes.
- 0 e2e regressions; new contract test that fetches `/feed.xml` and asserts well-formed XML + expected item count.
- Feed routes return 304 on conditional GETs (verified in unit tests).

## Rough Effort
S — three `Feed` subclasses, three URL entries, three `<link rel=alternate>` template additions, no migration, no new deps.

## Dependencies
- **10.05 Markdown Rendering Hardening** (Tier 1) — feed item bodies should reuse the same sanitized renderer. If that PRD changes the pipeline, feeds inherit the change for free, which is what we want.
