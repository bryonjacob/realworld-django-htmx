# PRD: Article Drafts and Unpublish

**Tier:** 1 &nbsp;·&nbsp; **Status:** Proposed &nbsp;·&nbsp; **Owner:** TBD

## Problem
`article_create_view` immediately publishes the article — there is no notion of an unpublished state. An author cannot save a work-in-progress, cannot stage edits before they go live, and cannot retract a published article without deleting it (which loses comments and favorites). For a writing tool this is a glaring omission; the "Publish Article" button label even implies a state transition that doesn't exist in the model.

## Goals
- Authors can save articles as drafts, visible only to themselves.
- Authors can unpublish a previously published article (back to draft) and republish later.
- The home feed and tag/search results show only published articles.

## Non-Goals
- Scheduled publishing ("publish at 9am Monday") — Tier 2.
- Version history / revisions — Tier 3.
- Per-draft sharing links for review.
- Multi-author drafts.

## User Stories
- As an author, I can click "Save as draft" on the editor and the article is stored without appearing in the global feed.
- As an author, I have a "My Drafts" tab on my profile that lists my unpublished articles.
- As an author, I can unpublish a live article and it disappears from feeds but stays editable.
- As a reader, I never see a draft article — direct slug URLs return 404.
- As an author, I see a clear status badge (Draft / Published) on my own profile listings.

## UX Sketch
Editor (`apps/articles` create + edit) gets two submit buttons: "Save as draft" and "Publish". The form posts to the same view; the button name disambiguates. After save, the author lands on the article detail page (which gains a banner "This article is a draft — only you can see it").

Profile page (`articles.views.profile_view`) gains a third tab alongside "My Articles" / "Favorited Articles": **"My Drafts"**, only rendered when viewing your own profile. Tab uses the existing HTMX-aware feed partial machinery.

Article detail for a draft gets an "Unpublish" / "Publish" button next to the existing Edit/Delete controls (author-only, same auth pattern).

`_feed_queryset` filters `status=published` for everything except the new "drafts" feed type. Direct article URL lookups for drafts 404 to non-authors.

## Data Model Changes
- `Article.status: CharField(choices=[("draft", "Draft"), ("published", "Published")], default="draft", db_index=True)`.
- `Article.published_at: DateTimeField(null=True, blank=True)` — set on first publish, used for sort order on the global feed (decoupling visible date from `created`).
- Data migration: existing rows get `status="published"`, `published_at=created`.

## Key Technical Decisions
- Use a **`status` enum field** rather than a boolean `is_published`. Forward-compatible with future states (scheduled, archived) without another migration. Alternative considered: boolean — simpler now but boxes us in.
- Sort the global feed by `published_at` not `created`, so unpublishing-then-republishing surfaces the article at its new publish time (matches user expectation).
- Extend `_feed_queryset` with a `"drafts"` feed type rather than a separate view — keeps the pagination/HTMX/partial codepath shared (per `apps/articles/CLAUDE.md`).

## Risks & Open Questions
- **Risk:** Slug collisions on republish — none, since slug is set at create time and never changes (`Article.save()` only slugifies when `pk is None`).
- **Open question:** Should comments on a published article be hidden when the author unpublishes? Recommendation: yes — comments are scoped to the article, so they vanish with it and reappear on republish. No data deletion.

## Success Metrics
- 0 e2e regressions; new e2e covers create-as-draft → publish → unpublish.
- Draft-write/published-read ratio observable via simple admin counts.
- 100% unit coverage maintained.

## Rough Effort
M — one migration with backfill, edits to the editor form/template, profile page tab, two new feed-queryset branches, banner on draft detail page, unit + e2e coverage.
