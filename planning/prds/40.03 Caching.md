# PRD: Caching

**Tier:** 4 &nbsp;·&nbsp; **Status:** Proposed &nbsp;·&nbsp; **Owner:** TBD

## Problem
The global feed (`/`) is the highest-traffic page on the site and currently rebuilds from the database on every anonymous hit — same 20 articles, same author lookups, same tag joins. Once we have any real traffic, that's wasted DB work and the slowest p95 on the site. The article-card partial is rendered identically thousands of times per day. We have no shared cache, no fragment cache, and no story for invalidation. Adding Redis (already coming for 40.02) gives us a cheap place to put hot reads.

## Goals
- Anonymous global feed served from cache for short windows (seconds, not minutes).
- Article-card partials cached as fragments keyed by article id + updated-at.
- Invalidation is correct: editing or deleting an article visibly updates within one cache TTL.

## Non-Goals
- Per-user feed caching ("Your Feed"). Cache hit rate is poor (each user's followed set differs) and complexity is high. Skip.
- Full-page caching of authenticated pages. CSRF tokens and the navbar avatar make this fragile.
- Caching at the CDN / reverse-proxy layer. Out of scope until 40.04 picks a deploy target.
- Querset-level caching libraries (`django-cachalot`, `cacheops`). They look magical but invalidate aggressively and hide cost — we want explicit caches we can reason about.

## User Stories
- As an anonymous reader, the homepage loads in <50ms p95 because it's served from cache.
- As an author, when I edit an article, the change shows up on the feed within the cache TTL window — and I see my own edit immediately on my profile.
- As a developer, I can disable the cache via env var to debug a "stale data" bug.
- As an operator, cache hit/miss counts surface in logs (40.01) so I can see whether the cache is doing anything.

## UX Sketch
No UI changes. Two layers:
- **Per-view cache** on the global feed view, anonymous-only, 30s TTL via `cache_page(30)` decorator gated on `request.user.is_anonymous`.
- **Template fragment cache** in `_article_card.html` keyed by `{{ article.id }}-{{ article.updated_at|date:'U' }}` — auto-invalidates on save because the key changes.

## Data Model Changes
None. (`Article.updated_at` already exists per the schema; if not, add it as part of this PRD — it's the natural cache key.)

## Key Technical Decisions
- **Backend: Django's `RedisCache` (built into Django 4.0+), not `django-redis`.** Built-in is sufficient for our needs and avoids a third-party dep. Alternative: `django-redis` (more features like connection pools, but unneeded).
- **Same Redis instance as 40.02**, separate logical DB (`/1` for cache, `/0` for jobs broker). One Redis to operate, two namespaces.
- **No cache-invalidation signals.** Use TTL + cache keys that include `updated_at`. Signal-based invalidation is famously buggy ("did the signal fire? did it fire on the right instance?"). Time + content-addressed keys are simpler and almost always correct.
- **Locmem fallback** when `CACHE_URL` is unset (dev, tests). Keeps the test suite hermetic — no Redis in CI.
- **Per-view cache is anonymous-only** because authenticated pages have personalized navbar (avatar, user menu). Use `vary_on_cookie` would defeat the cache entirely.

## Risks & Open Questions
- **Premature caching costs more than it saves.** A 30s TTL on the global feed adds debugging surface and "why isn't my change showing" confusion. Mitigation: ship behind a `CACHE_ENABLED` env var, default off in dev, on in prod. Measure before adding more layers.
- **Cache stampede on TTL expiry** under high load. Django's `cache_page` doesn't dogpile-protect. Acceptable at our (zero) scale; revisit with `django-cache-utils` or a soft-expiry pattern when traffic warrants.
- **Open question:** do we cache the rendered HTML of `_article_card.html` or the queryset behind it? Recommendation: HTML (fragment cache) — bytes are smaller and we skip template rendering.

## Success Metrics
- Anonymous `/` p95 latency drops from baseline by >70% under synthetic load.
- Cache hit rate on the article-card fragment >90% steady-state (logged hourly).
- 0 e2e regressions — Playwright suite must pass with cache enabled.

## Rough Effort
S — one settings block, one decorator, one `{% cache %}` tag. The thinking is the cost (key design, invalidation), not the code.
