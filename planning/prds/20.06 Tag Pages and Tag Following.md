# PRD: Tag Pages and Tag Following

**Tier:** 2 &nbsp;·&nbsp; **Status:** Proposed &nbsp;·&nbsp; **Owner:** TBD

## Problem
Tags today are clickable filters on the home feed (via `tag_view` in `apps/articles/views.py`), but there's no tag *landing page* — no way for a reader interested in `python` to subscribe to it, see how many articles use it, or read a description of what the tag means. Tags are also a discovery primitive that gets stronger when users can follow them: "show me a feed of everything tagged `django` or `htmx`" is exactly the killer feed for a technical blogging audience.

## Goals
- `/tag/<slug>/` is a real page with description, follower count, follow button, and the article list.
- A logged-in user can follow/unfollow a tag.
- Followed tags compose into a new feed filter on the home page: "Tags You Follow" (or stay as a separate feed tab).

## Non-Goals
- User-editable tag descriptions or wiki-style pages. Descriptions are admin-only for v1.
- Tag aliases or merging (`js` vs. `javascript`). The `taggit` library would handle this if needed; out of scope here.
- Trending-tag computation. The tag list is alphabetical / tag-cloud-by-count, same as today.
- Per-tag notifications. Out of scope.

## User Stories
- As a reader, I click `python` from the tag cloud and land on `/tag/python/` with a description and an article list.
- As a logged-in reader, I see a "Follow" button on the tag page and click it; my home page now offers a "Tags You Follow" feed tab.
- As a logged-in reader, "Tags You Follow" returns articles tagged with any of the tags I follow, newest-first, deduplicated.
- As an admin, I can edit a tag's description and a small icon URL via Django admin.
- As an anonymous visitor, the tag page works; the follow button redirects me to login.

## UX Sketch
New URL `/tag/<slug>/` rendered by a new `tag_landing_view`. Page top: tag name (h1), description (markdown-rendered), follower count, follow button. Below: the existing feed-card layout, scoped to that tag. Follow button does `hx-post` to `/tag/<slug>/follow` and swaps the button between Follow/Unfollow states (same pattern as `accounts.views.follow_view`). On the home page, the existing tab strip ("Your Feed | Global Feed | <selected tag>") grows a new permanent tab when the user follows ≥1 tag: "Tags You Follow." This becomes the third feed type in `_feed_queryset`.

## Data Model Changes
- New model `Tag(taggit.models.TagBase)` extending `taggit.models.Tag` via the `TAGGIT_TAGS_FROM_STRINGS` machinery — or a sidecar model `TagMeta(tag, description, icon_url)` linked OneToOne. The sidecar shape is less invasive and recommended.
- New model `TagFollow(user, tag, created)` with unique `(user, tag)` and indexes on `user` and `tag`.
- Migration is additive.

## Key Technical Decisions
- **Sidecar `TagMeta` over subclassing taggit's `Tag`.** Subclassing means changing the `TAGGIT_TAG_MODEL` setting, which is a project-wide reconfiguration; the sidecar is a fresh table with a OneToOne and zero risk to existing tag data. Alternative considered: full custom-tag-model swap — rejected as too invasive for the gain.
- **Reuse `_feed_queryset`.** The `apps/articles/CLAUDE.md` doc states this is the extension point for new feed types. "Tags You Follow" adds a `feed="followed_tags"` branch that does `Article.objects.filter(tags__in=user.tagfollow_set.values("tag"))`.
- **Tag descriptions sanitized** through the existing `markdown_filter.render_markdown` template tag (which already runs `nh3.clean`).

## Risks & Open Questions
- **Slug collisions.** taggit's slugs aren't always URL-safe (Unicode, case). Confirm `taggit.models.Tag.slug` is what we route on, and add a slug-uniqueness check.
- **Existing `tag_view`.** There's already a route for tag-filtered feeds. Resolve: redirect old `?tag=python` URLs to `/tag/python/`, or keep both? Probably keep both, with the landing page being the primary surface.
- **Open question:** does following 0 tags hide the "Tags You Follow" tab, or show it empty with an empty-state message? Hidden is cleaner.

## Success Metrics
- Tag landing page renders in <150ms (p95) for tags with thousands of articles.
- 100% coverage on `TagMeta`, `TagFollow`, and the new feed branch.
- E2e baseline stays green; new e2e covers the follow-tag-and-see-it-in-feed flow.

## Rough Effort
M — two new models, one new view, one new feed branch, admin tweaks. Light migration risk; existing tag-filter URL stays working.

## Dependencies
- None hard. Pairs naturally with a future search PRD ("10.02 Search" if it exists) — search and tag-following share the "what should I see" surface.
